# Reviewline

**เอเจนต์ดำเนินการสืบสวน มนุษย์เป็นผู้อนุมัติ**

[English](README.md) | **ภาษาไทย**

Reviewline คือสตูดิโอตรวจสอบเหตุการณ์ (Incident Review Studio) บนมาตรฐาน WebMCP สำหรับการทำงานร่วมกันอย่างไม่สมมาตรระหว่างมนุษย์และเอเจนต์ (Asymmetric Human–Agent Collaboration) โดยเบราว์เซอร์เอเจนต์จะทำหน้าที่ตรวจสอบการทำงานที่ล้มเหลวของเอเจนต์อัตโนมัติ ทำการจำลองรันซ้ำ (Replay) ราวกั้นความปลอดภัย (Guardrail) เทียบกับกรณีที่กระตุ้นให้เกิดปัญหาและกรณีควบคุมปกติ (Benign Control) จากนั้นจึงร่างข้อเสนอการตรวจสอบที่มีหลักฐานรองรับ ก่อนจะหยุดการทำงานที่เส้นแบ่งการตัดสินใจของมนุษย์อย่างชัดเจน

แอปพลิเคชันนี้เป็นระบบสาธิตสำหรับการแข่งขันที่ทำงานบนฝั่งไคลเอนต์ (Client-Only) ทั้งหมดอย่างแน่นอนชัดเจน (Deterministic): ไม่มีการเชื่อมต่อแบ็กเอนด์, ไม่ใช้ข้อมูลลับ/กุญแจ API จริง, ไม่มีการจ่ายเงินจริง, ไม่มีการปรับใช้นโยบายไปยังระบบภายนอก, ไม่เรียกใช้โมเดลภาษาภายนอก และไม่มีการกู้คืนสถานะข้ามเซสชัน การโหลดหน้าเว็บใหม่ (Reload) หรือกดปุ่มรีเซ็ต (Reset) จะเริ่มเซสชันใหม่ในหน่วยความจำเสมอ

---

## ทำไมต้อง WebMCP

Reviewline ใช้ WebMCP มากกว่าเพียงการเข้าถึงแดชบอร์ดแบบมีชนิดข้อมูลกำกับ (Typed Access):

- **สถานะที่ใช้ร่วมกัน (Shared State):** ทุกการเรียกใช้เครื่องมือจะโฟกัสหรืออัปเดตหลักฐาน, การจำลองรันซ้ำ, ข้อเสนอ และบันทึกการตรวจสอบ (Audit Log) ในสถานะเดียวกันกับที่ผู้ตรวจทานมองเห็นบนหน้าจอ
- **วงจรชีวิตตามหลักสิทธิ์ขั้นต่ำสุด (Least-Authority Lifecycle):** เครื่องมือจะถูกลงทะเบียนและยกเลิกการลงทะเบียนไปตามขั้นตอนของเวิร์กโฟลว์ เอเจนต์จะได้รับเฉพาะเครื่องมือที่จำเป็นและมีประโยชน์ในขั้นตอนปัจจุบันเท่านั้น
- **เส้นแบ่งผลกระทบโดยมนุษย์ (Human Consequence Boundary):** ปุ่มอนุมัติ (Approve) และปฏิเสธ (Reject) จะไม่มีทางปรากฏใน WebMCP manifest เด็ดขาด ผู้ตรวจทานที่เป็นมนุษย์จะต้องระบุตัวตน, บันทึกหมายเหตุ, ยืนยันหลักฐาน และกดปุ่มเลือกผลลัพธ์ผ่านหน้าจอ UI เท่านั้น
- **อินเทอร์เฟซรองรับสองภาษา (Bilingual Operations Interface):** สลับภาษาได้ทันทีระหว่างภาษาอังกฤษและภาษาไทย (`EN / TH`) ครอบคลุมทั้งส่วนแสดงผล UI, บทสรุปเหตุการณ์, ร่องรอยหลักฐาน และไทม์ไลน์เซสชัน โดยยังคงมาตรฐานโปรโตคอลเครื่องมือ WebMCP เป็นภาษาอังกฤษดั้งเดิม
- **เครื่องมือจำลอง Agent แบบอินเทอร์แอคทีฟ & คู่มือ ELI5 (In-App Interactive Test Harness & ELI5 Guide):** มีหน้าต่างคู่มืออธิบายแนวคิดเข้าใจง่าย (`?`) เรื่อง "เอเจนต์สืบสวน มนุษย์อนุมัติ" พร้อม 4 ตัวอย่างงานจริงระดับองค์กร และแถบ Tool Inspector ด้านล่างมีปุ่มสั่งรันแต่ละเครื่องมือ (`▶ สั่งรัน`) พร้อมปุ่มทางลัดจำลองการทำงานของ Agent 3 ขั้นตอนอัตโนมัติ (`⚡ รันการสาธิต Agent 3 ขั้นตอน`) บนเบราว์เซอร์ปกติได้ทันที

> [!NOTE]
> การไม่เปิดเผยเครื่องมือตัดสินใจแก่เอเจนต์เป็น **ขอบเขตขีดความสามารถของผลิตภัณฑ์ (Product Capability Boundary) ไม่ใช่หลักประกันการเข้ารหัสลับ (Cryptographic Guarantee)** ต่อการควบคุมเบราว์เซอร์อัตโนมัติทุกรูปแบบ Reviewline มุ่งเน้นการจำกัดขอบเขตอำนาจให้แคบลงและตรวจสอบได้ ไม่ได้อ้างว่า DOM เป็นกำแพงความปลอดภัยที่ไม่มีวันเจาะผ่านได้

## วงจรชีวิตของขีดความสามารถ (Capability Lifecycle)

| ขั้นตอนเวิร์กโฟลว์ | เครื่องมือ WebMCP ที่เปิดให้ใช้งาน |
|---|---|
| **การสืบสวน (Investigation)** | `list_incidents`, `inspect_incident` |
| **เลือกเหตุการณ์แล้ว (Incident selected)** | + `simulate_guardrail_patch` |
| **การจำลองรันซ้ำผ่านอย่างสมบูรณ์ (Clean replay ready)** | + `draft_review_gate` |
| **รอการตัดสินใจของมนุษย์ (Awaiting human decision)** | `list_incidents`, `inspect_incident`, `get_review_status` |
| **ตัดสินใจเรียบร้อยแล้ว (Decided)** | `list_incidents`, `inspect_incident`, `get_review_status` |

> `approve`, `reject`, `activate` และ `deploy` จะ**ไม่ถูกเปิดเป็นเครื่องมือเด็ดขาด** รายการเครื่องมือที่พร้อมใช้งานปัจจุบันและไทม์ไลน์เซสชันแบบต่อท้ายเท่านั้น (Append-Only) สามารถตรวจสอบได้บนหน้าจอแอปตลอดเวลา

## เส้นทางตัวอย่าง 3 นาที (Three-Minute Hero Journey)

1. เริ่มต้นด้วยเหตุการณ์จำลอง 3 รายการ; เลือกเหตุการณ์ฝ่ายจัดซื้อระดับวิกฤต (`inc-001`)
2. เรียกใช้เครื่องมือ `inspect_incident` เนื้อหาที่คล้ายคำสั่งแทรกแซงยังคงแสดงให้มนุษย์เห็นบนหน้าจอ แต่จะถูกส่งกลับไปยังเอเจนต์ในรูปแบบหลักฐานที่มีป้ายกำกับว่าเนื้อหาไม่น่าเชื่อถือ (`[UNTRUSTED-CONTENT]`)
3. เรียกใช้เครื่องมือ `simulate_guardrail_patch` โดยกำหนดเพดานบล็อกวงเงินที่ `$50,000`
4. ตรวจสอบผลลัพธ์เปรียบเทียบก่อน-หลัง: คำสั่งซื้อที่กระตุ้นปัญหา (`c-001-a`) ยังคงถูก **BLOCKED**, คำสั่งซื้อของผู้ขายปกติ (`c-001-b`) ยังคงได้รับอนุญาต **ALLOWED** และไม่มีเคสถดถอย (Regressions เป็น 0)
5. เรียกใช้เครื่องมือ `draft_review_gate` ความสามารถในการร่างจะถูกนำออกจาก manifest และเปิดให้ตรวจสอบสถานะผ่าน `get_review_status` แทน
6. มนุษย์กรอกชื่อผู้ตรวจทานและหมายเหตุ, ตรวจสอบหลักฐาน และเลือกกด **ยืนยันเพดาน $50,000; ระงับการสั่งซื้อไว้ต่อไป** หรือ **ปฏิเสธข้อเสนอ; คงการบล็อกเดิมไว้**
7. เรียกใช้เครื่องมือ `get_review_status` จะได้ผลลัพธ์การตัดสินใจกลับมาโดยระบุ `actor: human`; คำสั่งซื้อที่ถูกบล็อกจะยังคงไม่ได้รับอนุมัติ และไม่มีการปรับใช้นโยบายไปยังระบบภายนอก

## เริ่มต้นใช้งาน (Quick Start)

```bash
npm install
npm run dev             # เปิดที่ http://localhost:5173
```

- บนเบราว์เซอร์ทั่วไป จะมีหน้าต่าง **WebMCP Tool Inspector** จำลองการสั่งรันเครื่องมือแบบโต้ตอบได้จริง พร้อมปุ่มรันการสาธิต Agent อัตโนมัติในคลิกเดียว
- บนเบราว์เซอร์ Chromium ที่รองรับ WebMCP จะเปิดเผยเครื่องมือเนทีฟผ่านออบเจกต์ `document.modelContext`

## การตรวจสอบคุณภาพ (Verification)

```bash
npm test                # รัน Vitest ทั้งหมด (Unit, Component, Integration)
npm run typecheck       # ตรวจสอบ TypeScript ไม่มี emit
npm run lint            # ตรวจสอบ ESLint ด้วยนโยบาย 0 warning
npm run build           # ตรวจสอบ Production bundle build
npm run e2e             # รัน Playwright ครอบคลุมการสลับภาษา i18n และขนาดปุ่ม 44px
npm run audit:security  # ตรวจสอบช่องโหว่ความปลอดภัยระดับ moderate
npm run smoke:native    # รันการทดสอบ Native WebMCP บน Chrome 152
```

คำสั่ง `npm run smoke:native` ค่าเริ่มต้นจะมองหา Chrome ที่ `/usr/local/bin/google-chrome` (สามารถกำหนดตัวแปรสภาพแวดล้อม `CHROME_BIN` เพื่อระบุพาธของ Chrome ได้) สคริปต์นี้จะเปิด Chromium พร้อมแฟล็ก `--enable-features=WebMCP,DevToolsWebMCPSupport`, ดำเนินการส่งอาร์กิวเมนต์/รับผลลัพธ์เป็น JSON-string ตามสเปก Chrome 152, จำลองการตัดสินใจของมนุษย์ผ่าน UI และตรวจสอบความถูกต้องของ manifest ตลอดทั้งกระบวนการ

## แค็ตตาล็อกเครื่องมือ (Tool Catalogue)

| เครื่องมือ | เจตนาของคำอธิบาย (Annotation Intent) | วัตถุประสงค์ |
|---|---|---|
| `list_incidents` | อ่านอย่างเดียว, ข้อมูลไม่น่าเชื่อถือ | รายการสรุปเหตุการณ์จำลองที่มีขอบเขตจำกัด |
| `inspect_incident` | อ่านอย่างเดียว, ข้อมูลไม่น่าเชื่อถือ | ร่องรอยหลักฐานและกลุ่มเคส พร้อมโฟกัสเหตุการณ์บนหน้าจอ |
| `simulate_guardrail_patch` | อ่านอย่างเดียว, ข้อมูลไม่น่าเชื่อถือ | จำลองการรันซ้ำแบบแน่นอนชัดเจนและตรวจจับเคสถดถอยอย่างสมมาตร |
| `draft_review_gate` | เปลี่ยนแปลงสถานะ, ข้อมูลไม่น่าเชื่อถือ | สร้างข้อเสนอการตรวจสอบที่รอดำเนินการจากการจำลองรันซ้ำที่ผ่านเกณฑ์ |
| `get_review_status` | อ่านอย่างเดียว, ข้อมูลไม่น่าเชื่อถือ | อ่านบันทึกการตรวจสอบของมนุษย์ รวมถึงข้อความที่มนุษย์กรอก |

ทุกสคีมามีระบบตรวจสอบความถูกต้องในขณะทำงานแยกเป็นอิสระ: ปฏิเสธค่าว่าง/ไม่ใช่ object, ตรวจจับคีย์แปลกปลอม, ตรวจสอบเพดานตัวเลขจำนวนเต็ม, ปฏิเสธข้อความขนาดยาวเกินกำหนด, ตรวจสอบรหัสที่ไม่รู้จัก และป้องกันการจับคู่ระหว่างการจำลองกับเหตุการณ์ที่ไม่ตรงกัน ความพร้อมในการร่างจะถูกคำนวณใหม่จากฟิกซ์เจอร์ข้อมูลตั้งต้น และมีกรอบการลงทะเบียนกลางที่จำกัดปริมาณข้อมูลส่งออกของเอเจนต์
